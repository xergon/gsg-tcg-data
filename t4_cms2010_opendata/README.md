## 5. 🔴 FINDINGS — read these before computing anything

### 5.1 AOD/AODSIM is uproot-readable WITHOUT CMSSW — but not the piece HOJD needs most

This was measured, not assumed: uproot 5.6.9 opened the files directly over HTTPS range reads.

**READABLE (verified in `cms-5` DATA, `cms-776` Pythia6 and `cms-750` Herwig++ alike — 39 split sub-branches for jets, 49 for PF candidates):**
- `recoPFJets_ak5PFJets__RECO.` → `pt_`, `eta_`, `phi_`, `mass_`, and every `m_specific.*` PF energy fraction and multiplicity
- `recoPFCandidates_particleFlow__RECO.` → per-particle `pt_`, `eta_`, `phi_`, `mass_`, `pdgId_`, vertex, ECAL/HCAL raw energies
- `double_ak5PFJets_rho_RECO.` (pileup density)

**NOT READABLE:**
- 🔴 `recoPFJets...obj.dau` — the jet→constituent `edm::PtrVector`. uproot raises `NotImplementedError: memberwise serialization of AsArray`.
  **The CMS jet's own constituent list cannot be read.** Constituent-level HOJD observables (e2/e3/D2, any EFP)
  therefore require **re-clustering anti-kt R=0.5 from the full `particleFlow` PFCandidate collection**, which is readable.
  That is the same operation the MIT MOD 2011A release performed, so the two legs remain methodologically comparable —
  but it is a re-clustering, not a read, and it must be stated in the method.
- 🔴 `GenEventInfoProduct_generator__SIM.`, `recoGenJets_ak5GenJets__SIM.`, `recoGenParticles_genParticles__SIM.` are
  **unsplit** in AODSIM (4 wrapper sub-branches only). **The per-event generator weight and `pthat` are NOT obtainable
  without CMSSW.** Only the dataset-level pT-hat / HT bin (from the dataset name) is available. Any cross-section
  weighting across bins must come from an external table, not from the files.

### 5.2 run / lumi / event ARE recoverable — fixed-offset byte parse of `edm::EventAuxiliary`

`EventAuxiliary` fails uproot deserialization (`DeserializationError`, `edm::Hash<2>` version 9). But the branch's raw
basket byte segments carry run/lumi/event as big-endian `uint32` at **byte offsets 43 / 47 / 51**.

Validated on the full file `00052C5A-EF70-E011-B43F-00266CF32A00.root` (33 baskets, 5,679 events):
one run **146511**, lumisections **182–189** (8 distinct), event numbers **100% unique**, lumi **monotone non-decreasing**,
and **5,679 / 5,679 events (100.00%) fall inside the golden JSON**. That last number is the real check — a wrong offset
would not land inside a 273-run certified list.

⚠ **Do not hard-code 43/47/51.** The offset depends on the file's ProcessHistoryID/process-GUID layout. Locate it per
file by scanning basket 0 for the offset at which the `uint32` lies inside the record's declared run range for *every*
entry — that is exactly how these offsets were found, and it is a two-line scan.

**⇒ The validation mask CAN be applied, and the full HOJD pipeline CAN be run on 2010 AOD, entirely without CMSSW.**

### 5.3 `mJetArea == 0.0` in the 2010 AOD

All **108,120** ak5PFJets in the checked `cms-5` file have `mJetArea == 0.0` (min = max = 0). Jet area is not populated
in this reprocessing, so stored-area `rho * A` pileup subtraction is unavailable. `double_ak5PFJets_rho_RECO.` is present
and readable, so area must be recomputed at re-clustering time (fastjet active areas) if it is needed.

### 5.5 There is no MOD-style derived product for 2010

The 2011A leg already delivered (`t4-cms2011a-*`) came from the MIT MOD HDF5 release (Zenodo 3340205 / 3341498 / 3341500).
**No equivalent exists for 2010.** A portal-wide search of CMS derived datasets returns, for 2010, only PAT-format
lepton skims (`cms-201`, `cms-202`), education/masterclass event files, and per-dataset event-display files — nothing
jet-level. The 2010 leg is AOD/AODSIM or nothing.

### 5.6 7 TeV Herwig++ QCD exists ONLY for 2010

A portal search for `herwigpp` returns 37 records: 13 TeV MiniAODSIM (2015), one 8 TeV ZH (2012), and the
**Summer12-LowPU2010** 7 TeV QCD family. So **2010 is the only year where Pythia6, Herwig++ and MadGraph+Pythia6 QCD
coexist at 7 TeV** — the three-family design is only realisable on this year. Two extra Herwig++ 7 TeV records the
thread did not name are also public and may help: **`cms-743`** `/QCD_Pt-15to3000_Tune23_Flat_HFshowerLibrary_7TeV_herwigpp/...-v2/AODSIM`
and **`cms-741`** `/QCD_Pt-15to1000_fwdJet_bwdJet_TuneEE3C_Flat_7TeV_herwigpp/...`.

### 5.7 Year mismatch against the delivered STAGE1

`STAGE1_LOW2` (2,397,697 jets) is **CMS 2011A**, Pythia6, `Summer11`/MOD. Everything in this manifest is **2010**,
`Summer12-LowPU2010_DR42`, global tag `START42_V17B::All` (MC) / `FT_R_42_V10A::All` (data), CMSSW **4.2.8**,
**zero-pileup `PU_S0`** simulation. Different year, different tune era, different pileup scenario, different JEC.
The 2010 set is internally self-consistent — do not join it to the 2011A table without a stated transfer step.

## 6. What was DEFERRED, and exactly why

- **The 6.265 TB of AOD/AODSIM bytes were NOT mirrored.** Re-hosting is pointless as well as impossible here: GitHub's
  release-asset cap is 2 GiB, and the thread's runtime cannot materialise release-asset binaries at all. Every file is
  instead directly fetchable from CERN by the `https_url` in the per-record index — nothing is lost.
- **The 3.879 TB on tape is not fetchable by any route available to an agent** (see §5.4). Its manifest is published in
  full — filename, byte count, publisher adler32, and both the hot and cold URIs — so a recall can be requested against
  an exact list.
- **No derived per-jet feature table was produced this pass.** §5.1/§5.2 establish that one *is* producible without
  CMSSW; building it is a separate compute job (re-cluster anti-kt R=0.5 from PFCandidates), not an enumeration pass.
